Summary

This repo mixes long-form papers, specs, and notes exported from Word and written by hand. The goal is a cohesive reading experience on GitHub and on the GitHub Pages site under docs/, without losing your voice—only improving structure, math notation, tables, and consistency.

Goals

Phase C — Git & GitHub Pages

  1. Branch (optional): editorial/<folder-slug> for big folders; merge to main when the wave is done.
  2. Commit message convention:
    editorial: pass <FolderName> — tables, headings, math cleanup
  3. Pages: Settings → Pages → /docs on main.
  4. After each merged wave: python tools/build_github_pages.py and commit docs/ if HTML changed.

Per-folder checklist (copy into PR / issue)

Use this for every editorial pass:

  • [ ] Headings: logical # / ## / ###; no accidental ## from numeric table cells; numbered sections consistent.
  • [ ] Math: prefer \( … \) / \[ … \] or $…$ / $$…$$; no broken italics inside formulas (see UHPM fixes as example).
  • [ ] Tables: replace “stacked __Column__” blocks with GFM pipe tables where a grid is intended.
  • [ ] Emphasis: prefer **bold** for strong emphasis; use __ sparingly (or normalize in a controlled batch).
  • [ ] Links & assets: no empty ](); images referenced exist or note “asset missing”.
  • [ ] Typos: filenames (Millitary → Military when you rename), units (kHz), superscripts (e.g. x¹⁰ not x¹°).
  • [ ] Duplicates: if two files are full duplicates, one should point to the canonical file (see Statistical Generation/README.md).
  • [ ] Run: python tools/normalize_markdown_corpus.py (if raw Word paste), then python tools/build_github_pages.py.
  • [ ] Spot-check the generated HTML under docs/site/ for that folder.
