Neural Decompiler

Neural Decompiler\README.md

Summary

A runnable PyTorch implementation of a sequence-to-sequence neural decompiler: assembly-like tokens are encoded and decoded into a higher-level token sequence (demo data uses C-like snippets). The architecture follows the intent of the original design sketch: hierarchical memory, a transformer encoder–decoder, and a mixture-of-experts (MoE) layer split into “binary” and “language” families.

Research note (architecture + objectives): RESEARCH.md.

A runnable PyTorch implementation of a sequence-to-sequence neural decompiler: assembly-like tokens are encoded and decoded into a higher-level token sequence (demo data uses C-like snippets). The architecture follows the intent of the original design sketch: hierarchical memory, a transformer encoder–decoder, and a mixture-of-experts (MoE) layer split into “binary” and “language” families.

The previous single-file draft (archive/Neural_Decompiler_design_sketch.py.txt) mixed Markdown fences with Python, contained invalid syntax (e.g. await in non-async methods), and referenced many undefined types. That artifact is kept only as a reference; the code you run lives under neural_decompiler/.

Requirements

  • Python 3.10+
  • PyTorch 2.x (see requirements.txt)

Install:

pip install -r requirements.txt

Quick start

From this directory (Neural Decompiler):

python -m neural_decompiler.train --epochs 5 --samples 800 --device cpu

Optional checkpoint (stores vocabs, config, and samples/seed for inference):

python -m neural_decompiler.train --epochs 10 --checkpoint checkpoints/demo.pt

Validation: by default ~12% of examples are held out; each epoch prints val_loss and val_tok_acc (masked token accuracy). Disable with --val-ratio 0.

Greedy decode after training (use the same --samples and --seed as training, or rely on values saved in the checkpoint):

python -m neural_decompiler.infer checkpoints/demo.pt --device cpu

You can also run the thin entry script:

python "Neural Decompiler.py" --epochs 2 --device cpu

Package layout

Module Role
neural_decompiler/config.py EnhancedDecompilerConfig (model size, MoE, memory, training).
neural_decompiler/memory.py AdvancedMemoryManager (slot memory + attention), HierarchicalMemoryTransformer.
neural_decompiler/experts.py FamilyMoELayer: routed mixture of feed-forward experts + load-balancing loss.
neural_decompiler/model.py NeuralDecompilerModel: encode → MoE → decode with teacher forcing.
neural_decompiler/dataset.py SyntheticDecompilerDataset, vocabulary helpers, collation.
neural_decompiler/train.py CLI training loop (AdamW, label smoothing, MoE aux loss, optional val metrics).
neural_decompiler/infer.py Load .pt checkpoint and print source / reference / greedy hypothesis.
neural_decompiler/metrics.py Masked token accuracy, batch eval helper, optional corpus BLEU.
neural_decompiler/text.py Inverse vocab and id→token helpers for printing.

Method (short)

  1. Source embedding + hierarchical memory compresses and conditions token representations on learnable memory slots.
  2. A Transformer encoder builds contextualized representations of the binary/ASM side.
  3. A MoE refines hidden states; routers are encouraged to use all experts via an auxiliary MSE loss toward a uniform target.
  4. A causal Transformer decoder with cross-attention generates target tokens; optimization uses cross-entropy with label smoothing.

Extending to real data

Replace SyntheticDecompilerDataset with a loader that:

  1. Tokenizes lifted assembly or IL (or fixed-width instruction fields) on the source side.
  2. Tokenizes C/C++/IR on the target side (separate vocabularies are supported).
  3. Emits padded tensors compatible with collate_fn (or your own batching).

Tune EnhancedDecompilerConfig (hidden_size, layer counts, MoE sizes) for your GPU memory.
